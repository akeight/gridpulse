# GridPulse

## Overview

GridPulse is a machine learning and data engineering project exploring how historical electricity consumption can be used to forecast future demand, identify high-usage periods, and understand changing energy consumption patterns.

The project begins with individual household smart-meter data and will progressively explore distribution feeder data, transformer loading, and more advanced temporal machine learning architectures.

## Business Problem

Electricity demand fluctuates throughout the day, across seasons, and in response to changing consumer behavior. Accurate forecasting can help energy providers anticipate demand, improve resource planning, and identify periods of unusually high usage.

**Primary research question:**

> Can historical electricity consumption data be used to forecast electricity demand 24 hours ahead more accurately than a seasonal-naive baseline?

**Primary goal:** Build a reproducible data pipeline and forecasting model that improves upon simple historical baselines while avoiding data leakage.

**Secondary goals:**
- Explore daily, weekly, and seasonal electricity consumption patterns.
- Identify periods of unusually high consumption.
- Evaluate how the amount and recency of historical training data affect forecasting performance.
- Investigate model performance across different seasons and time periods.

### Project Scope

The initial dataset contains measurements from **one household in France**, collected between December 2006 and November 2010.

This dataset is suitable for learning time-series data engineering and forecasting. It does not represent an entire electrical distribution network and cannot directly establish transformer overload risk or modern grid electrification trends.

Future project phases may use feeder-level and transformer-level datasets to investigate utility-specific forecasting and equipment-loading questions.

## Dataset

**Individual Household Electric Power Consumption**

- Source: UCI Machine Learning Repository
- Dataset: https://archive.ics.uci.edu/dataset/235/individual+household+electric+power+consumption
- Observations: Approximately 2.08 million minute-level records
- Period: December 2006 – November 2010
- Sampling frequency: Approximately one minute
- License: CC BY 4.0

The raw dataset includes electrical measurements such as global active power, global reactive power, voltage, current intensity, and sub-metering values.

### Initial Target Variable

`Global_active_power` represents household active power, measured in kilowatts (kW).

The initial processing pipeline aggregates minute-level active-power readings into **hourly mean active power (kW)**.

This represents average electrical demand during an hour, not total energy consumption in kWh.

For a complete hour, average power in kW multiplied by one hour gives the corresponding energy in kWh.

### Missing Data

The original dataset contains missing measurements.

The preprocessing pipeline is intended to:
- Parse timestamps from the original date and time columns.
- Convert active-power measurements to numeric values.
- Aggregate observations into hourly mean active power.
- Count valid minute-level measurements per hour.
- Preserve missing-data information rather than automatically imputing values.

Hours with fewer than 60 valid minute readings must be reviewed before modeling.

**Important:** The preprocessing script and its behavior will be verified before relying on the processed data.

## Machine Learning Plan

### Phase 1 — Data Engineering and Exploration

- Validate raw and processed timestamps.
- Examine missing values and incomplete hours.
- Explore daily, weekly, and seasonal patterns.
- Visualize electricity demand over time.
- Introduce SQLite storage and SQL-based exploration.

### Phase 2 — Forecasting Baselines

Start with a **24-hour-ahead point forecast** of hourly mean active power.

At prediction time `t`, the model predicts demand at `t + 24 hours` using only information available at or before `t`.

- Define the target and forecast horizon.
- Create chronological train, validation, and test splits.
- Establish simple naive and seasonal-naive baselines.
- Evaluate forecasting errors using MAE and RMSE.

### Phase 3 — Feature Engineering and Traditional ML

- Create calendar and cyclical time features.
- Engineer lagged consumption features.
- Calculate historical rolling averages and variability.
- Train and compare regression models such as linear regression, Random Forest, and XGBoost.
- Evaluate performance against the baseline.

All features must be calculated using information available at prediction time.

### Phase 4 — Temporal Evaluation and Concept Drift

- Compare different historical training-window lengths.
- Evaluate performance by season and time period.
- Experiment with walk-forward validation.
- Investigate changes in consumption patterns over time.
- Evaluate whether more recent training data improves performance.

### Phase 5 — Advanced Modeling & Research Extensions (Future)

Explore advanced machine learning architectures for electricity demand forecasting, anomaly detection, and intelligent grid monitoring.

These experiments will build upon established forecasting baselines and may use additional datasets containing feeder-level measurements, transformer characteristics, equipment connectivity, or labeled anomalies.

The objective is to investigate whether more sophisticated architectures provide measurable improvements over traditional machine learning approaches.

#### 5.1 — Temporal Deep Learning

Investigate neural-network architectures designed to learn patterns and dependencies across time.

Potential architectures:
- **LSTM (Long Short-Term Memory):** Learn long-term dependencies in historical electricity consumption.
- **GRU (Gated Recurrent Unit):** Explore a simpler recurrent architecture for temporal forecasting.
- **TCN (Temporal Convolutional Network):** Use causal convolutions to capture temporal patterns across multiple time scales.
- **PatchTST:** Investigate transformer-based forecasting using patches of historical time-series observations.

**Research question:** Can temporal deep learning models improve 24-hour-ahead electricity demand forecasting compared with traditional machine learning baselines?

Compare forecasting accuracy, training costs, inference efficiency, and generalization across seasons.

#### 5.2 — Graph Neural Networks & Grid Intelligence

Explore graph-based machine learning architectures capable of modeling relationships between connected electrical infrastructure.

Potential architectures:
- **GCN (Graph Convolutional Network):** Learn spatial relationships between connected grid components.
- **GAT (Graph Attention Network):** Learn which neighboring nodes contribute most strongly to predictions.
- **T-GCN (Temporal Graph Convolutional Network):** Combine graph convolution with temporal learning to model connected grid behavior over time.
- **TGNN (Temporal Graph Neural Network):** Investigate broader temporal graph architectures, including dynamic graphs and time-dependent interactions.
- **Temporal graph attention models:** Explore attention-based learning across both network connections and historical observations.

**Research question:** Does incorporating physical grid connectivity improve transformer loading or overload-risk predictions compared with independent time-series forecasting models?

Potential applications:
- Transformer load forecasting.
- Distribution feeder congestion prediction.
- Equipment stress and overload-risk assessment.
- Spatial-temporal anomaly detection.
- Modeling changes in electricity demand across connected infrastructure.

**Dataset requirement:** Graph-based modeling requires suitable network topology, node-level measurements, and time-aligned observations. The initial UCI household dataset does not provide these.

NREL SMART-DS is a potential dataset for future graph-based experiments.

#### 5.3 — Generative Models & Synthetic Anomaly Detection

Investigate whether generative models can help address the scarcity of real-world electrical faults and abnormal consumption events.

Potential approaches:
- **GANs (Generative Adversarial Networks):** Generate synthetic observations resembling patterns learned from training data.
- **Recurrent or conditional GANs:** Explore architectures designed for sequential or condition-dependent synthetic data generation.
- **R-GAN variants (to be verified):** Investigate the previously discussed Advanced R-GAN approach after confirming its specific architecture and suitability.
- **Generative anomaly detection:** Explore models that learn normal operating behavior and identify observations that deviate from expected patterns.

**Research question:** Can physically plausible synthetic rare-event data improve electrical anomaly detection compared with models trained only on real observations?

Potential applications:
- Rare equipment-fault detection.
- Abnormal household or feeder consumption.
- Transformer stress and unusual loading patterns.
- Data augmentation for imbalanced anomaly datasets.
- Evaluating anomaly-detection robustness under rare operating conditions.

Potential experiments:
1. Establish baseline anomaly-detection models using methods such as Isolation Forest, autoencoders, or supervised classifiers.
2. Identify suitable real-world datasets containing labeled faults or anomalies.
3. Train generative models using only the training partition.
4. Generate and evaluate synthetic anomaly examples for physical plausibility, temporal consistency, and diversity.
5. Compare detection performance with and without synthetic augmentation.
6. Evaluate on untouched real-world test data using precision, recall, F1, and PR-AUC.

**Important:** Synthetic anomalies are not equivalent to verified equipment faults. Generative augmentation may not improve generalization and must be validated against real observations.

#### 5.4 — Combined Research Opportunities

If earlier experiments establish suitable datasets and strong baselines, explore combining temporal, graph-based, and generative approaches.

Potential directions:
- **Temporal graph anomaly detection:** Detect abnormal behavior across connected grid components over time.
- **Graph-based synthetic augmentation:** Investigate whether generated rare events can improve detection of anomalies affecting multiple connected components.
- **Changing-grid generalization:** Evaluate model robustness under changing EV adoption, distributed energy resources, weather patterns, and load distributions.
- **Advanced temporal graph architectures:** Explore newer research approaches, including the previously discussed Temporal Janus concept, after verifying the relevant model or paper.

**Long-term research question:** Can models that combine temporal patterns, physical grid relationships, and rare-event augmentation improve forecasting and anomaly detection under changing grid conditions?

#### Research Principles

Advanced models will be evaluated against established baselines rather than assumed to be superior.

Experiments should prioritize:
- Reproducible training and evaluation.
- Chronological data splits and prevention of future leakage.
- Appropriate datasets for each modeling approach.
- Controlled comparisons and multiple random seeds where relevant.
- Performance across seasons and changing operating conditions.
- Computational efficiency and practical utility relevance.

These are exploratory research directions, not required deliverables for the initial GridPulse forecasting pipeline.

## Evaluation Principles

GridPulse will prioritize reproducibility and realistic evaluation.

1. **No future leakage:** Predictive features must be available at the forecast issuance time.
2. **Chronological evaluation:** Avoid random train/test splitting for time-series forecasting.
3. **Baseline comparison:** Complex models must be evaluated against simple historical forecasts.
4. **Data-quality awareness:** Missing and incomplete observations must be handled explicitly.
5. **Reproducibility:** Record data transformations, model configurations, evaluation periods, and random seeds where applicable.
6. **Realistic claims:** Household consumption forecasting must not be presented as validated transformer-overload prediction.

### Classical Machine Learning & Forecasting Baselines

These papers are being explored for traditional machine learning experiments, baseline comparisons, and forecasting evaluation methodology.

**1. Comparative Performance Evaluation of Machine Learning Models for Short-Term Residential Load Forecasting (2026)**

- [Read paper](https://www.icaiit.org/paper.php?paper=14th_ICAIIT_4%2F7_23)
- Examines Linear Regression, Random Forest, and XGBoost using the UCI Individual Household Electric Power Consumption dataset.
- **GridPulse relevance:** Directly related to our dataset and next-hour forecasting experiments.

**2. Comparing Peak Electricity Load Forecasting Models for an Industrial and a Residential Building (2026)**

- [Read paper](https://www.sciencedirect.com/science/article/pii/S0378475425002629)
- Investigates electricity peak-demand forecasting and persistence-based benchmarks.
- **GridPulse relevance:** Naïve forecasting baselines, day-ahead evaluation, and peak-demand prediction errors.

**3. Short-Term Load Forecasting Models: A Review of Challenges, Progress, and the Road Ahead (2023)**

- [Read paper](https://www.mdpi.com/1996-1073/16/10/4060)
- Reviews statistical forecasting, traditional machine learning, and deep learning approaches.
- **GridPulse relevance:** Understanding model selection, feature engineering, and comparative forecasting methodology.

**4. Short-Term Electrical Load Forecasting at a 15-Minute Resolution: A Benchmarking Study (2026)**

- [Read paper](https://www.mdpi.com/1996-1073/19/13/3211)
- Compares seasonal naïve forecasting, statistical methods, gradient-boosted trees, and deep learning.
- **GridPulse relevance:** Benchmark design, chronological evaluation, and comparisons between simple and complex forecasting models.

*Research status: These papers are candidates for further review and do not represent implemented or reproduced experiments.*
